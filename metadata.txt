about=Filter your layers without writing SQL: build the query with drop-downs (field, operator and the layer's real values, including null and empty values, checkbox lists, AND / OR and groups) and the plugin writes the SQL for you. The operators are those of ArcGIS: is (not) equal to, is one of, contains, (does not) start or end with, is (not) between, is on / before / after for dates, and more. Save several named filters per layer inside the project and switch between them from the layer's right-click menu. Use any query as a filter or as a selection, select the features visible in the map view, create a filter from the current selection, and check how many features match before applying it. Warnings catch common mistakes (misspelled values, ambiguous numbers such as 1.000, AND and OR mixed without a group, filters that keep nothing, fields that were renamed). The SQL is written for each format (GeoPackage, Shapefile, GeoJSON, FileGDB, PostGIS, CSV and more), so accents, upper/lower case, underscores, percent signs and dates filter the same everywhere. Syncs with QGIS 'Filter...' and includes Processing tools. Interface in English, Spanish and Portuguese (follows the QGIS language).

changelog=
    1.1.0 - More operators, as in ArcGIS: does not start with, does not end with, is not between; dates use «is on», «is before», «is after»… and a date alone means the whole day.
          - Value lists offer «Empty» (a text with nothing written) besides «Null», and show spaces at the start or end as ␣.
          - A date-time or decimal picked from the list always finds its features (milliseconds, 15-digit rounding in GeoJSON and FlatGeobuf).
          - Virtual layers: «contains» and similar now ignore upper/lower case, as in the other formats.
          - Much faster long lists of texts in Shapefile, GeoJSON and other GDAL formats.
          - Select visible features follows the Temporal Controller.
          - New warnings: AND and OR mixed without a group, and data sources the plugin has not been tested with.
          - Changing the operator or the field of a clause keeps only the values that still make sense.
          - Damaged or hand-edited saved queries no longer cause errors.
    1.0.0 - First public release.
